# Out Loud 0.2.1

Focused native SAPI volume fix for external SAPI clients and Voice Manager.
The product version comes from `ProductVersion.props`; model revision, model
compatibility identity, OLV v1 format, AppId and SAPI CLSID are unchanged.
The bundled OLP remains SHA-256
`fe8c40e3a773465974ce965e57f01c8904ac4cb2cf7086c42cbb151f8815ba3e`;
the tokenizer remains
`45ffaf8c702dbb6c954bd54280d83ea00f8bf1d47692aca37e078c8deb26935a`.
Model provenance and voice-quality guidance remain in the [0.2.0 notes](0.2.0.md).

The adapter now queries initial baseline volume and refreshes it on
`SPVES_VOLUME`, retaining the last valid level when a query fails (default 100).
SAPI baseline and fragment percentages combine multiplicatively. Signed PCM16
is scaled after speech-rate processing, including flushed Sonic tails, with
wide arithmetic, nearest/ties-to-even rounding and saturation. Zero writes
silent samples without dropping them; unity bypasses scaling exactly. Partial
writes always rescale the remaining original samples using the latest volume.

Equal-volume fragments retain the existing concatenated text/synthesis path.
Actual fragment volume transitions form separate rendering runs; the previous
run drains before its fragment factor changes. A surrogate pair crossing a
fragment boundary remains intact at the leading character's volume. Changing
volume across text runs can introduce synthesis/phrasing boundaries; no sample
alignment from text to already generated neural audio exists in this adapter.
Whitespace-only volume runs remain attached to neighboring text. Gain processing
itself changes no sample counts, duration or playback speed.

Voice Manager already explicitly selects `SAPI.SpVoice` volume 100 and rate 0.
Normal playback leaves SAPI's default audio output in place. No production
frontend changes, gain stage or Windows volume queries were added. Windows
master/per-application volume remains part of normal speaker playback.

Focused validation uses synthetic PCM through the actual adapter control/write
path, fragment collection/run dispatch and Sonic. It requires no model or voice
loading, installed registration, audio device or production error-log access.
The managed `--sapi-volume` check exercises the existing tester playback and
automation implementation with injected objects, without running other suites.

Package with the existing production workflow and unchanged asset/signing policy:

```powershell
.\installer\inno\build-stage.ps1 -StageDirectory "$PWD\generated\installer\stages\release-0.2.1"
.\installer\inno\verify-stage.ps1 -StageDirectory "$PWD\generated\installer\stages\release-0.2.1"
.\installer\inno\build-installer.ps1 -StageDirectory "$PWD\generated\installer\stages\release-0.2.1" -OutputDirectory "$PWD\generated\installer\compiler-output\release-0.2.1" -PreserveHistoricalInstallers
```

The existing numeric upgrade path accepts 0.2.0 to 0.2.1, preserving the
installation identity, voices and configuration. The installer stays publisher
unsigned; installation-owned signing occurs only when the user runs setup.
This preparation does not execute setup or deploy anything. Manual installation,
audible WoW/tester playback, live client volume changes and Windows Volume Mixer
behavior remain to be verified by the user after installation.
