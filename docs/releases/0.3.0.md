# Out Loud 0.3.0

Updates the English model from `english_2026-09_2` to official Kyutai
`english_2026-10`. The native C++ inference architecture, SAPI CLSID, installer
AppId, OLV v1 format and the volume handling fixed in 0.2.1 are preserved.
The installer is prepared locally for manual installation and listening tests.
It has not been executed or published by this preparation.

## Architecture and text compatibility

Configuration and upstream operator review establish the existing topology:
FlowLM 6 layers, width 1024, 16 heads of 64, FFN 4096 and RoPE period 10000;
LSD sampler 6 layers of 512 with two time conditions and one decode step;
32-dimensional latents; Mimi 2 layers of 512 with 8 heads, FFN 2048, context 250,
SEANet ratios 6/5/4, mono 24 kHz and 1920 samples per latent frame.
Temperature 0.3 and EOS threshold -4 remain appropriate configuration defaults.

The v4.0.1 source adds optional low-rank embeddings, projected backbone outputs,
different attention/KV widths, alternate sampler types and independent decoder
configurations. This English configuration enables none of them: optional fields
default to None, attention uses the existing full width/head count, sampler type
defaults to LSD, and decoder configurations use the original shared definitions.
The changed Mimi upsample constructor resolves to the same decoder width, 512.
Compatibility was not inferred solely from the layer count.

The source tokenizer is unchanged, so the packaged tokenizer was preserved
byte for byte. The new English configuration enables replacement of U+2018 and
U+2019 with straight apostrophes. Its upstream preparation path also joins Unicode
whitespace and removes a comma, semicolon or colon immediately after sentence
punctuation. Native text preparation now follows that path. The reference
text-chunking module used by the existing offline fixture tooling is byte-identical
to v4.0.1; no Python environment or Pocket TTS Studio update was required.
The original schema's `pocket_version` and compatibility-hash domain retain the
reviewed 3.3.0 converter/preparation lineage; `active-model.json` records the new
upstream release and immutable checkpoint separately.

## Voice compatibility and validation

Supported OLV v1 profiles retain six FP32 key/value prefixes, 16 heads and head
dimension 64, with unchanged layout, bounds and integrity checks. The loader does
not reject an otherwise supported profile because its serialized preparation
identity differs from the active model identity. Existing OLV and prepared
Safetensors fixtures loaded and synthesized with the new model; scratch import
and export preserved the voice bytes and identity.

Existing user voices were not regenerated, converted or modified. A separate
scratch profile was prepared from the existing development recording solely for
validation. No installed application, managed VoiceLibrary or Pocket TTS Studio
was changed.

Focused validation passed:

- Source published size/SHA-256, complete schema/dtype and finite-value checks.
- Exact BF16 conversion, all retained tensor bytes, OLP metadata and integrity.
- Native model loading, corrupt model rejection and invalid voice rejection.
- Fifteen upstream text/tokenization cases plus preparation and UTF-8 edge checks.
- Fresh scratch, older OLV and imported prepared-voice synthesis: finite PCM,
  completed requests and EOS reached.
- Number sample: `Bring 12 coins and 3.5 pounds of ore. The total is 42.`
  produced 122,880 finite samples and reached EOS.
- Existing voice input hashes and packaged tokenizer remained unchanged.

Audio files and detailed logs are under
`generated/model-updates/release-0.3.0/validation` and
`generated/release-0.3.0`. These checks do not establish intelligibility, correct
number pronunciation, speaker similarity or acoustic equivalence. Older cloned
voices may sound different or exhibit artifacts; listening remains necessary.

## Installer and manual verification

Build with the existing production workflow:

```powershell
.\installer\inno\build-stage.ps1 -StageDirectory "$PWD\generated\installer\stages\release-0.3.0"
.\installer\inno\verify-stage.ps1 -StageDirectory "$PWD\generated\installer\stages\release-0.3.0"
.\installer\inno\build-installer.ps1 -StageDirectory "$PWD\generated\installer\stages\release-0.3.0" -OutputDirectory "$PWD\generated\installer\compiler-output\release-0.3.0" -PreserveHistoricalInstallers
```

Deliverable: `release/OutLoud-Setup-0.3.0.exe`, with its `.exe.sha256` checksum.
Windows 11 native x64 requirements, payload allowlist, signing policy and
license/consent UI are unchanged. The new source model card declares CC BY 4.0;
its prohibited-use paragraph exactly matches the already bundled policy.
Updated attribution identifies the new checkpoint without rewriting history.

The established workflow produces a publisher-unsigned installer. Installation-owned
signing runs only when the user executes setup and reuses existing installation
ownership during upgrades. No certificate is created or used during this build.

The unchanged in-place release-maintenance path supports 0.2.1 to 0.3.0 without
uninstalling. It preserves the installation location, signing identity, managed
voice profiles/metadata/IDs, registrations and user configuration. Voices are
excluded from the installer payload. Numeric version and package checks are
performed during preparation; actual upgrade, recovery and preservation on a live
installation remain manual verification because setup is not executed here.

After manual installation, listen to ordinary and numeric samples with representative
older voices, verify Voice Manager and external SAPI playback, confirm the 0.2.1
volume behavior and check the existing library/registrations. No commit, tag,
push or GitHub Release is created by this preparation.
